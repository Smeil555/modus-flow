# MODUS FLOW

Система обратной связи: React/TypeScript, FastAPI, SQLAlchemy, SQLite и отдельный HTTP-симулятор 1С:УТ. Симулятор не является 1С. Состав реализованного и оставшиеся задачи перечислены в [PROJECT_STATUS.md](PROJECT_STATUS.md). Используйте только синтетические данные: проект ещё не готов к промышленной эксплуатации.

## Запуск в Windows PowerShell

Из корня проекта, Python 3.11+:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Push-Location frontend-react
npm ci
npm run build
Pop-Location
$env:SESSION_SECRET = 'замените-на-случайное-значение-не-короче-32-символов'
$env:DEMO_PASSWORD = 'задайте-уникальный-демо-пароль'
python -m alembic upgrade head
python -m scripts.seed
python -m uvicorn mock_1c.main:app --port 8001
```

Во втором окне PowerShell перейдите в корень проекта, активируйте окружение, повторите установку `SESSION_SECRET` и запустите `python -m uvicorn backend.main:app --port 8000`. Откройте http://localhost:8000. Логины: `employee`, `admin`, `manager`, `executor`; пароль задаётся `DEMO_PASSWORD` при первом запуске seed. Повторный seed не меняет существующие пароли. API: http://localhost:8000/docs, симулятор: http://localhost:8001/docs. Если React не собран, сервер выдаст старый интерфейс прототипа; для актуального интерфейса обязательно выполните `npm ci` и `npm run build`.

В третьем окне активируйте то же окружение и запустите `python -m scripts.deadline_worker`. Он проверяет сроки каждую минуту и создаёт внутренние уведомления; для однократного запуска планировщиком используйте `python -m scripts.deadline_worker --once`. У всех процессов должен быть одинаковый `DATABASE_URL`; приложение за прокси должно получать проверенный адрес клиента и использовать одинаковый `SESSION_SECRET` во всех экземплярах. Ограничитель хранит в общей базе только HMAC технического ключа, а не IP или токен обращения.

Локально зависимости могут быть установлены в `.vendor`: вместо активации venv задайте `$env:PYTHONPATH = '.vendor;.'`. В защищённой среде нужны HTTPS, `COOKIE_SECURE=1`, отдельные секреты, внешний ограничитель запросов и полноценный аудит безопасности.

Для базы предыдущего прототипа без Alembic сначала остановите сервер и выполните `python -m scripts.upgrade_legacy`. Скрипт создаёт резервную копию `modus.db.pre-alembic.bak`, добавляет новые поля и таблицы и отмечает начальную миграцию. Он работает только с локальной SQLite и отказывается перезаписывать резервную копию. Для новой базы используйте `alembic upgrade head`.

## Демонстрация

1. Войдите как employee и отправьте анонимное обращение «На складе не работает сканер штрихкодов». Сохраните показанный один раз токен.
2. Войдите как admin, откройте обращение и назначьте предложенный технический отдел.
3. Войдите как manager и назначьте executor. Исполнитель открывает обращение, запрашивает товары, создаёт тестовую заявку и отмечает решение.
4. Admin видит историю и показатели. Employee может открыть анонимное обращение через токен.

SQLite хранит хеш токена, но не автора анонимного обращения. Не вводите имя и идентифицирующие детали в тексте: система не может автоматически гарантировать их отсутствие. Сетевые и серверные журналы могут содержать технические метаданные. Для анонимного обращения доступны PNG и JPEG: сервер перекодирует изображение, удаляет исходное имя и метаданные. Содержимое изображения может раскрыть личность: проверьте его перед отправкой. PDF и текстовые файлы в анонимном режиме не принимаются.

Администратор может назначить пользователю дополнительные роли и отделы. Пользователь переключает только назначенный рабочий контекст; изменение назначений отзывает его текущие сессии. Срок, введённый в браузере в местном времени, хранится в UTC.

## Проверка

`python -m pytest -q` при установленном `PYTHONPATH`; `npm test` и `npm run build` в `frontend-react`. Для согласованного снимка базы выполните `python -m scripts.backup backup/modus-backup.db`; скрипт не перезаписывает существующий файл. Для согласованной копии вместе с файлами остановите изменения, отдельно скопируйте каталог `uploads` и проверьте восстановление. Не добавляйте пользовательские базы и резервные копии в Git. `mock1c.db` содержит только тестовые заявки симулятора.

## 1С:УТ

Интеграция по умолчанию демонстрационная: отдельный сервис возвращает товары и остатки, а также создаёт тестовые заявки с idempotency key. Заготовка реального клиента ожидает специально согласованный HTTPS-сервис с тем же контрактом и Basic Auth; она не проверялась на настоящей 1С. Для реальной 1С понадобятся согласованные интерфейсы, права сервисной учётной записи, схема данных, TLS и проверка бизнес-правил. См. [описание интеграции](docs/1c.md).
