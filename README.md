# MODUS FLOW

Система обратной связи: React/TypeScript, FastAPI, SQLAlchemy, SQLite и отдельный HTTP-симулятор 1С:УТ. Симулятор не является 1С. Состав реализованного и оставшиеся задачи перечислены в [PROJECT_STATUS.md](PROJECT_STATUS.md). Используйте только синтетические данные: проект ещё не готов к промышленной эксплуатации.

## Запуск в Windows

1. Установите Python 3.11 или новее и Node.js с npm. Проверьте команды `python --version` и `npm --version` в новом окне PowerShell.
2. Откройте [Open-Modus-Flow.bat](Open-Modus-Flow.bat) двойным щелчком. Первый запуск устанавливает зависимости, собирает React и применяет миграции.
3. При первом запуске введите в консоли выданный временный пароль для `Smeil`. Ввод скрыт. Для запуска без подсказки передайте пароль через переменную окружения `INITIAL_ADMIN_PASSWORD`. После создания аккаунта seed больше не читает эту переменную для него.
4. На странице [MODUS FLOW](http://localhost:8000) войдите под логином `Smeil` с временным паролем. Панель администратора откроется сразу после входа.
5. Для остановки нажмите Ctrl+C в консоли запуска. Скрипт завершит запущенные им процессы. Повторный запуск открывает уже работающий проект.

При обновлении существующего проекта сначала остановите его процессы. При первом запуске скрипт переносит содержимое `modus.db` в `operations.db` через резервное копирование SQLite. Исходный файл остаётся на месте. Если `operations.db` уже существует, используется он. Для базы старого прототипа без Alembic сначала выполните `python -m scripts.prepare_database`, затем `python -m scripts.upgrade_legacy` из окружения проекта. Перед обновлением остановите также все процессы, использующие эту базу.

### Управление аккаунтами

Браузер обращается к основному Backend на порту 8000. Backend обслуживает React и передаёт запросы к данным по внутреннему HTTP. Отдельный процесс FastAPI Data Service слушает `127.0.0.1:8002`, проверяет служебный токен и права пользователя и работает с `operations.db`. Основной Backend дополнительно проверяет права на административных маршрутах. SQLite хранит связи между аккаунтами, отделами, сессиями и обращениями.

Скрипт запуска ждёт готовности Data Service и Backend, затем запускает симулятор 1С на порту 8001 и открывает браузер. Проверка `http://localhost:8000/health` показывает доступность Backend и Data Service. Для прямого запроса к `/health` Data Service нужен служебный токен. Запланированные напоминания обрабатываются внутри Data Service.

- Откройте **Управление пользователями → Создать аккаунт**. Укажите логин, временный пароль от 12 символов, роль и отдел. Для руководителя отдела и исполнителя отдел обязателен. Передайте пользователю начальный пароль отдельно. Пользователь может изменить его в профиле.
- В таблице можно искать по логину и фильтровать по роли или отделу. В форме **Изменить** задайте логин, роль, отдел и состояние. Чтобы заблокировать пользователя, снимите отметку **Аккаунт активен** и сохраните. Верните отметку, чтобы разблокировать. Система защищает последнего активного главного администратора.
- Через **Разрешения** выдавайте и отзывайте доступ к аналитике, журналам, состоянию базы, категориям и отделам. Там же можно назначить дополнительную роль в другом отделе. После изменения разрешений пользователь может обновить страницу, чтобы обновилось меню. Изменение роли, отдела или блокировка отзывает сессии другого пользователя.
- Через **Сбросить пароль** задайте новый временный пароль. Все сессии аккаунта завершатся. Пользователь может войти с выданным паролем и изменить его в профиле.
- В **Журнале действий** видны изменения аккаунтов и их авторы. В **Состоянии базы** отображаются имя файла, движок и версия SQLite. В **Системных настройках** выбирается режим интеграции с 1С. Для режима REAL заранее задайте в окружении сервера `REAL_1C_URL`, `REAL_1C_USER` и `REAL_1C_PASSWORD`.

Системный уровень `SUPER_ADMIN` управляет аккаунтами, справочниками и настройками. На уровне администрации `ADMIN` и `ADMIN_ASSISTANT` настраивают маршруты и руководителей, контролируют ошибки и участвуют в пересмотрах. Начальник `DEPARTMENT_MANAGER` и заместитель `DEPARTMENT_DEPUTY` работают в назначенном отделе. `EMPLOYEE` создаёт и отслеживает свои обращения. Любой подходящий сотрудник отдела может стать исполнителем конкретного обращения. `EXECUTOR` сохранён для существующих аккаунтов и открывает только назначенные задачи.

### Настройка обработки обращений

1. Войдите как системный администратор. Создайте аккаунт администрации и сотрудников, указав отдел каждого сотрудника.
2. Войдите под аккаунтом администрации и откройте **Отделы и роли**. Назначьте начальника и при необходимости заместителя. Сотрудник может переключиться на назначенную роль через **Рабочая роль**.
3. В **Категории и маршруты** опубликуйте маршрут для каждой используемой категории. Система ведёт версии и направляет новые обращения по действующей версии. Если маршрут или ответственный отсутствуют, подача блокируется, а администрация получает уведомление.
4. В **Контроль обращений** администрация видит сведения о категории, отделе, ответственном и статусе. В **Пересмотрах отказов** представитель администрации получает доступ к карточке конкретного обращения после подключения к процедуре.

### Изменение своего пароля

Откройте **Профиль → Настройки аккаунта → Безопасность → Изменить пароль**. Введите текущий пароль, новый пароль от 12 символов и подтверждение. Нажмите **Сохранить новый пароль**. После сохранения старый пароль перестанет работать, а другие сеансы завершатся.

### Запуск из PowerShell

Из корня проекта выполните `.\Open-Modus-Flow.bat`. Если зависимости установлены и задан `SESSION_SECRET` длиной от 32 символов, можно выполнить `.\.venv\Scripts\python.exe -m scripts.run_services`. Перед первым запуском можно задать `INITIAL_ADMIN_PASSWORD` в окружении. Супервизор подготавливает базу и запускает все процессы в правильном порядке.

Обслуживание SQLite, включая резервное копирование, выполняйте при остановленном проекте. Data Service не обращается к `reference.db`.

## Демонстрация

Создайте тестовых пользователей с нужными ролями через панель. Для автоматического создания прежних демо-аккаунтов запустите seed с переменной `DEMO_PASSWORD` длиной от 12 символов.

1. Войдите как employee и отправьте анонимное обращение «На складе не работает сканер штрихкодов». Сохраните показанный один раз токен.
2. Проверьте, что обращение автоматически поступило руководителю по опубликованному маршруту. Руководитель принимает его на рассмотрение, назначает сотрудника своего отдела и срок.
3. Исполнитель открывает **Мои задачи**, запрашивает товары, создаёт тестовую заявку и передаёт результат. Руководитель подтверждает результат и закрывает обращение.
4. Автор видит результат. При отказе автор может подать мотивированный запрос. Первый запрос допускается автоматически, для следующих требуется решение администрации. Пересмотр завершается при согласии руководителя и представителя администрации.

SQLite хранит хеш токена, но не автора анонимного обращения. Не вводите имя и идентифицирующие детали в тексте: система не может автоматически гарантировать их отсутствие. Сетевые и серверные журналы могут содержать технические метаданные. Для анонимного обращения доступны PNG и JPEG: сервер перекодирует изображение, удаляет исходное имя и метаданные. Содержимое изображения может раскрыть личность: проверьте его перед отправкой. PDF и текстовые файлы в анонимном режиме не принимаются.

Администратор может назначить пользователю дополнительные роли и отделы. Пользователь переключает только назначенный рабочий контекст; изменение назначений отзывает его текущие сессии. Срок, введённый в браузере в местном времени, хранится в UTC.

## Проверка

`python -m pytest -q` при установленном `PYTHONPATH`; `npm test` и `npm run build` в `frontend-react`. Для согласованного снимка базы выполните `python -m scripts.backup backup/modus-backup.db`; скрипт не перезаписывает существующий файл. Для согласованной копии вместе с файлами остановите изменения, отдельно скопируйте каталог `uploads` и проверьте восстановление. Не добавляйте пользовательские базы и резервные копии в Git. `mock1c.db` содержит только тестовые заявки симулятора.

## 1С:УТ

Интеграция по умолчанию демонстрационная: отдельный сервис возвращает товары и остатки, а также создаёт тестовые заявки с idempotency key. Заготовка реального клиента ожидает специально согласованный HTTPS-сервис с тем же контрактом и Basic Auth; она не проверялась на настоящей 1С. Для реальной 1С понадобятся согласованные интерфейсы, права сервисной учётной записи, схема данных, TLS и проверка бизнес-правил. См. [описание интеграции](docs/1c.md).
