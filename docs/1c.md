# 1С:Управление торговлей в MODUS FLOW

## Сценарий

Исполнитель получает обращение о неисправном сканере, ищет оборудование через MODUS FLOW и видит тестовый артикул и остаток по складу. Если замены нет, он создаёт демонстрационную заявку. Номер заявки и ответ сервиса сохраняются в истории обращения. Источник этих данных сейчас — отдельный Mock 1C, а не корпоративная база.

## Как подключить реальную систему

1. Согласовать версию и конфигурацию 1С:УТ, владельцев объектов, доступные поля и перечень складов.
2. Определить опубликованные OData-объекты для чтения либо отдельный HTTP-сервис. Создание заявки согласовать как отдельную операцию с правами и проверками 1С.
3. Создать техническую учётную запись с минимальными правами, настроить TLS и хранение секретов. Проверить доступность и ограничения сети.
4. Реализовать отдельный Real1CClient, сопоставление идентификаторов и полей, идемпотентность и обработку ошибок. Проверить на тестовой базе; не считать доступность объектов универсальной.
5. Согласовать мониторинг, правила повторов, сверку статусов и регламент запуска. Передавать только данные, необходимые операции; анонимные тексты и личность автора не отправлять без отдельного основания.

## Границы текущей реализации

Сервис MOCK предоставляет поиск товаров с остатком и создание заявки с идемпотентным ключом. API получения статуса заявки у симулятора есть, но интерфейс обновления статуса и реальный адаптер пока не реализованы. История сохраняет ответы интеграции в SQLite; секреты в ней не записываются.
